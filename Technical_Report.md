### Abstract
This report details the design, implementation, and performance evaluation of an autonomous differential-drive line-following robot. The system leverages an ESP32 microcontroller for hardware interfacing (sensors, encoders, motor drivers) connected via Wi-Fi to a host laptop running ROS 2 Humble. The robot utilizes an array of five infrared sensors for line detection and high-resolution wheel encoders for unicycle kinematic odometry. A centralized Proportional-Integral-Derivative (PID) controller processes the sensory input to compute real-time angular velocity corrections, enabling robust navigation along a closed-loop track. Experimental results confirm that the kinematic model effectively tracks the robot's pose, and the tuned PID parameters achieve smooth, high-speed line tracking with minimal lateral deviation.

---

### 1. System Description
The robotic platform is a differential-drive vehicle consisting of:
*   **Microcontroller:** ESP32 handling low-level hardware actuation and sensor data streaming over Wi-Fi (UDP) using `micro_ros_arduino`.
*   **Actuators:** Two DC motors driven by an L298N H-bridge motor driver.
*   **Sensing:** A 5-channel Infrared (IR) reflectance sensor array mounted at the front, and two incremental wheel encoders mounted on the motor shafts.
*   **Host Computer:** Laptop running ROS 2 Humble, responsible for high-level computing, PID control, odometry integration, and web-based telemetry visualization.

The separation of low-level I/O (ESP32) and high-level logic (ROS 2) creates a highly scalable and robust architecture.

---

### 2. Sensing
The robot perceives the line using five digital IR sensors (`l2`, `l1`, `mid`, `r1`, `r2`). These sensors detect the presence of a highly reflective white line on a black background (returning a digital `HIGH` value when over the line). 
The ESP32 reads these states and streams them to the ROS 2 network at 50Hz via the `/raw/sensor_*` topics.
The `line_sensor_node.py` computes a normalized lateral error using a weighted centroid formula, applying specific weights (`2.0`, `1.0`, `0.0`, `-1.0`, `-2.0`) to estimate exactly how far off-center the line is.

---

### 3. Actuation
The ESP32 subscribes to the `/motor/left/pwm` and `/motor/right/pwm` topics to command the L298N driver.
A fail-safe mechanism is hardcoded into the ESP32: if no commands are received from the ROS 2 host for over 500ms, both motors are instantly brought to a halt. This satisfies the strict Emergency Stop (e-stop) and safety requirements of the project.

---

### 4. ROS Architecture
The software stack is built as a highly modular ROS 2 system utilizing the `line_follower_core` package:
1.  **`micro_ros_agent`**: Bridges the Wi-Fi UDP stream from the ESP32 into the ROS 2 graph.
2.  **`line_sensor_node`**: Aggregates the 5 IR topics and publishes a `std_msgs/Float32` on `/line_error`.
3.  **`line_controller_node`**: Subscribes to `/line_error` and computes a `geometry_msgs/Twist` published to `/cmd_vel` using a PID algorithm.
4.  **`motor_driver_node`**: Converts `/cmd_vel` into left and right PWM `Int32` messages based on the unicycle inverse kinematics.
5.  **`encoder_odometry_node`**: Integrates raw encoder ticks into a `nav_msgs/Odometry` message on `/odom`.

### 7. Discussion
The experimental data indicates that the ROS 2 based architecture provides a sufficiently low latency loop (via UDP) to support high-speed PID control. The initial use of Proportional control caused oscillations, which were effectively dampened by the introduction of the Derivative term. The Kickstart pulse implementation solved initial static friction issues smoothly without causing long-term instability.
